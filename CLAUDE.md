# Doc Works — Obsidian .docx / .pptx / .xlsx editor

@AGENTS.md

GPL-3.0.

## Commands

- `npm test` — vitest (jsdom). `DOC_WORKS_DECKS=<dir>` / `DOC_WORKS_DOCS=<dir>` / `DOC_WORKS_BOOKS=<dir>` also round-trip every real .pptx / .docx / .xlsx there (workbooks: byte-identical no-op saves, every supported formula recalculated against the file's cached result, an edit + reload).
- `npm run check:files -- <folder>` — all of the above on every .docx / .pptx / .xlsx under a folder (e.g. `~/notes`): byte-identical no-op writes, edited copies via `tests/export-samples.test.ts`, and, when LibreOffice is found (`SOFFICE=<path>`), the LibreOffice warnings each edit adds over its original. Run it after any writer change.
- Layout check: `soffice --headless --convert-to pdf` then `pdftotext -bbox-layout` gives LibreOffice's line positions to compare with the page view. Only trust it for fonts LibreOffice has metric clones of (Arial, Times, Courier); it renders Aptos as Liberation Serif (`pdffonts` shows what it used).
- `npm run check:pages -- [vault folder]` — in the running Obsidian: opens every .docx, compares the page count with the one Word saved (docProps/app.xml) and checks every drawn page is the paper's height. Run it after any layout / font change.
- `npm run typecheck` — `tsc --noEmit` (lib ES2022).
- `npm run lint` — eslint-plugin-obsidianmd (what the community directory scanner checks); keep it at 0 errors. Use `attrsOf<T>()` for ProseMirror attrs instead of `node.attrs.x`.
- `npm run build` — bundles everything (jszip, prosemirror) into `main.js`. Ship only `main.js`, `manifest.json`, `styles.css`.

## Layout

- `src/core/` — xml namespaces/helpers, `History<T>` undo stack, `utils/fonts.ts` (CSS font stacks with metric-compatible fallbacks, shared by both views and by text measuring).
- `src/infrastructure/ooxml/ooxml-package.ts` — shared OPC zip: every XML part as a live DOM, rels, content types, media, snapshot/restore, save. With `dirtyOnly` (xlsx) save writes only parts passed to `touch` (plus new/removed ones), so untouched parts keep their bytes.
- `src/infrastructure/xlsx/xlsx-workbook.ts` — workbook package: sheets found through relationships (tab order, sheetId, rId, path kept apart), shared strings, add/delete sheet parts, `dropCalcChain`.
- `src/infrastructure/blank.ts` — blank 16:9 deck / Letter document / one-sheet workbook for the New presentation / document / spreadsheet commands.
- `src/infrastructure/{pptx,docx}/` — format packages on top of it (slide ops incl. layouts/`setLayout`, background, `setSlideSize`, p14 sections kept in step by `adjustSections`; docx main part, images, numbering/`ensureList`).
- `src/domain/pptx/` — `color.ts`, `geometry.ts` (DrawingML formula engine: presets from generated `preset-shapes.ts` + custGeom -> SVG paths, text rects, connection sites, adjust handles), `shape-style.ts` (fill/line/shadow read incl. theme style matrix, CSS, writers in schema order), `slide-model.ts` (layout/master inheritance, text style chain), `slide-edit.ts` (minimal-diff text writer incl. numbering/spacing/links/fields, bodyPr settings, shape insert/transform/z-order/connectors), `table.ts` (a:tbl read with table-style regions resolved per cell; row/col insert/delete, merge/split keeping hMerge/vMerge consistent, fills, borders, built-in style XML for tableStyles.xml; cells are `kind: "cell"` shapes listed right after their table), `find.ts` (find/replace over slide text incl. cells), `chart.ts` + `chart-format.ts` (chart data with its embedded workbook; type/stacking/title/legend/labels/axes/colours read and written as a diff, converting between bar/line/area/pie/doughnut), `animation.ts` (p:transition and p:timing main sequence read from behaviours, not preset ids: one step per click, effect delays, paragraph targets, a small evaluator for #ppt_x-style formulas), `arrange.ts` (items = direct children of spTree: bounds, group/ungroup, align/distribute, snapping, copy/paste with id + rel remapping), `links.ts` (text and shape links: web, `#slide:<part>` = hlinksldjump + slide rel, `#jump:nextslide` etc.; links to a deleted slide are dropped, pasting into another deck drops slide links), `picture-adjust.ts` (alphaModFix / lum / grayscl / duotone, drawn as an inline SVG filter), `paint-format.ts` (copy fill, line, shadow, first run style + alignment onto other shapes).
- `src/domain/docx/` — `pages.ts` (page setup from sectPr, `paginate` estimate), `revisions.ts` (list / accept / reject tracked changes on the XML), `drawing.ts` (picture / text box placement: wp:inline vs wp:anchor wrap modes read, drawn as CSS floats / blocks / absolute, rewritten by `setPlacement`; text boxes drawn from the opaque run XML), `textbox.ts` (a text box's w:txbxContent as an editor doc and back, fallback VML copy kept in step; `presentation/docx/docx-textbox-view.ts` edits it in place with a nested editor), `sections.ts` (sections: each w:sectPr kept as XML on its paragraph / the doc attr `sectPr`; `regroup` wraps sections with 2+ columns in a display-only `columns` block, which commands rebuild after changing section XML; `sectionBreaks` for the page view), `schema.ts` (PM schema; lists = paragraph numId/ilvl, headings = styles, `opaque`/`raw_block` atoms hold XML we don't edit, `sdt` = editable content control around blocks (TOC is `kind: "toc"`), `field` mark = cached PAGE/NUMPAGES result the page view fills in, paragraph `tabLeader` = right tab stop drawn as a stretched flex tab; `keepNext` / `keepLines` null = from the style, row `cantSplit`), `docx-reader.ts` (body -> PM doc + `origins` key -> original XML; tracks complex fields `fldChar` begin/separate/end across runs and paragraphs), `docx-writer.ts` (verbatim copy if unchanged, else patch original pPr/rPr/tcPr in schema order), `docx-styles.ts` (display-only style CSS incl. style indents + list labels, table-style cell padding as `--docx-cell-*` variables), `math.ts` (OMML equations drawn as native MathML; edited as LaTeX: `ommlToLatex` / `latexToOmml`, new XML only for edited equations), `wrap.ts` (text on both sides of a mid-column picture: blanks planned line by line into a laid-out copy of each covered paragraph; `presentation/docx/docx-wrap.ts` turns them into widgets), `watermark.ts` (Word's VML watermark — PowerPlusWaterMarkObject text path / WordPictureWatermark picture — in a run of every header's first paragraph; the page view draws it from each page's header band with z-index -1 inside the isolated page), `style-edit.ts` ("Update '<style>' to match": the paragraph is written to a scratch body with the normal writer and its pPr / rPr merged into the w:style). Task lists from note export use `ensureList("task")` (numFmt none, bullet indents) with the box in a Segoe UI Symbol run.
- `src/domain/xlsx/` — spreadsheets, no Obsidian: `references.ts` (A1, ranges, sheet quoting), `formula.ts` (tokenizer keeping exact text, Pratt parser to an AST, reference rewriting: copy translation, row/column insert/delete shifts with #REF!, sheet renames), `number-format.ts` (format codes incl. sections/conditions/colors/dates, General, typed-input parsing like Sheets, `adjustDecimals`), `styles.ts` (cellXfs -> CSS and toolbar state, `derive` appends/reuses records, never edits shared ones; lookups cached since records are append-only), `workbook-model.ts` (sparse cells over the live sheet XML: each cell keeps its `<c>`, writes patch only it; shared formulas expanded on read and un-shared before an edit; `Axis` prefix sums for column/row positions; journal hooks for undo), `formula-evaluator.ts` (~90 functions, ranges stay references so SUM(A:A) reads only existing cells, `Unsupported` for anything not implemented), `calculation.ts` (`Calc`: column-bucketed dependency index, transitive recalculation, circular -> #REF! like Sheets, unsupported results keep their cache and mark themselves and dependents stale + `fullCalcOnLoad`; missing caches computed in memory on open), `commands.ts` (`Edits`: transactions journal cell elements for undo, structural edits journal whole parts and rebuild the model; typed input, clear, format, fill), `clipboard.ts`, `sheet-edit.ts` (rows/columns insert/delete rewriting formulas, names, merges, CF, validations, hyperlinks, filters, tables, drawing anchors and chart refs; sheets; sizes; freeze; merge; sort; filters), `find.ts`, `conditional.ts` (cfRule read / evaluated lazily per drawn cell / written; dxf styles in `styles.ts`), `validation.ts` (dataValidation lists and limits; `invalidateValidations` after edits), `charts.ts` (chart frames in the drawing part, data from live cells, insert / format / re-source / delete), `drawing.ts` (pictures from drawing anchors, `anchorBox`; a one-cell anchor at a cell's corner smaller than the cell is fitted to it, which is how Google exports in-cell images), `outline.ts` (row/column groups from outlineLevel; collapsed = summary row/column marked `collapsed` or all members hidden; grid draws them in a gutter that widens the headers), `cleanup.ts` (remove duplicates, split text to columns), `csv.ts` (RFC 4180 parse, displayed-value export, import as a new tab), `names.ts` (named ranges: add / set range / rename with formula rewrite / delete).
- `src/infrastructure/fonts/eot.ts` — Embedded OpenType -> TrueType (MTX / LZCOMP + CTF), a port of libeot kept under MPL-2.0; decks from Google Slides embed their fonts this way. Unlike libeot it writes composite glyphs' instruction length, the full glyf table and the head checksum, and drops the (unrebuilt) hdmx / VDMX, because browsers reject libeot's output. Dev check: `ots-sanitize` (nixpkgs opentype-sanitizer) on decoded fonts.
- `src/presentation/pptx/` — `embedded-fonts.ts` (registers a deck's fonts with FontFace while it's open), `text-html.ts`, `text-fit.ts` (letter-spacing to match Office font widths from generated `font-metrics.ts`, plus kerning from generated `font-kerning.ts`: slides when a:rPr kern applies, Word docs always), `slide-renderer.ts`, `slideshow.ts` (slideshow + presenter view, plain DOM; animation steps, auto-advance, transitions), `show-effects.ts` (plays steps and transitions with the Web Animations API on rendered slides; shapes found by `data-spids`), `shape-gallery.ts`, `shape-panel.ts` (format panel + slide panel for an empty selection, plain DOM), `pptx-view.ts`.
- `src/presentation/xlsx/` — `grid.ts` (plain DOM: native scroll container with a sticky viewport-sized canvas, four clipped panes for frozen rows/columns, each painted on a `<canvas>` from a list of paint ops (`paint.ts`; tests assert on `grid.ops`) because hundreds of fresh cell elements per frame cost 20–40 ms of style/layout against Obsidian's stylesheet; DOM only for selection, reference boxes, filter buttons and pictures; never read layout (scroll offsets, sizes) after writing DOM in `render`; one textarea is both the cell editor and the keyboard/IME sink and lives outside the scroller so typing never scrolls it; click-to-insert references while building a formula; fill handle, resize, header selection; dark theme maps white fills / black text), `xlsx-view.ts` (FileView, toolbar, formula bar + name box, sheet tabs, menus, filter dialog, find/replace, clipboard events, autosave, outside-change reload, PDF).
- `src/presentation/common/export-dialog.ts` — every export (PDF of documents / slides / sheets, note → DOCX, DOCX → Markdown, slide PNG, sheet CSV) goes through `exportDialog` (format with its options, file name, vault folder or "Outside the vault…" = the app's download, Replace warning, remembered "Open after export") and `writeExport`. `pdf.ts` only renders: `renderPdf` prints page boxes in a `.print` container via Electron `printToPDF` (docx pages from `printPages` in docx-pages: copies of the paged editor cut at the drawn gaps, positioned relative, not absolute: Chromium drops the bottom of absolutely placed copies; pptx pages are slides rendered at 96 dpi). `png.ts` `renderPng` draws a slide in a fixed overlay and captures it at 1920 px wide with the DevTools protocol's `Page.captureScreenshot` (attached/detached around it; `capturePage` returns stale frames while the window is unfocused). `save-status.ts` (Saved / Saving… / Couldn't save + Retry, auto-retry 5 s, 15 s, 60 s), `office-search.ts` (side panel searching every .docx/.pptx/.xlsx in the vault through `infrastructure/office-text.ts`, which unzips only the text parts; a result opens the file with its find bar on the query via `rememberSearch`), `find-bar.ts` (the find / replace bar all three editors build; each does its own searching), `autosave.ts` (the three editors' save scheduling, one save at a time, failures handed to SaveStatus; read-only files never saved), `keyboard.ts` (toolbars as one Tab stop with arrow keys, F6 regions, Escape in panels back to the editor, focus back after dialogs). `toolbar.ts`: Google-style menu row above each toolbar (`menu` builds an Obsidian `Menu` each time it opens; `menuItem`, and `subMenu`: Obsidian's own hover submenus via `MenuItem.setSubmenu`, which exists but isn't in the typings; the code marked `FALLBACK(submenu)` opens a second menu instead and can be deleted to save size) and one compact row: groups marked `pin` never fold, the others fold from the right into ⋮ when the row overflows (`fit`, run by a ResizeObserver; ⋮ items work the hidden controls, colours through a temporary picker); `context(test)` groups show only for a selection, re-checked by `sync()` from the views' selection updates. `narrow.ts`: `is-narrow` below 700 px; docked side panels hide and their toggles open them as drawers over the document (`openDrawer`: Escape / click outside closes; the docked state is kept).
- `src/presentation/docx/` — `docx-editor.ts` (PM commands incl. links, spacing, table merges, comment anchors, footnote refs, TOC; decorations incl. `fitText` letter-spacing to Word font widths via `pptx/text-fit.ts`; no Obsidian), `docx-pages.ts` (page view, `pageAt(state, pos)` for TOC page numbers: measures the text flow with page decorations hidden, `layoutPages` in `domain/docx/pages.ts` breaks between blocks (content controls opened up), paragraph lines and inside table cells; in-cell / in-paragraph breaks are spacer widgets carrying the page gap; keep with next / keep lines together / rows that can't split; first-page and even-page headers via `headerFooterType`; column sections hold N column-heights per page, measured as one column of the column width, gaps/spacers inside them are `column-span: all`), `docx-find.ts` (find/replace + word count), `docx-image-view.ts`, `cell-selection.ts` (Google's cell selection: a drag between cells selects the block of cells, one range per cell so marks / paragraph commands touch only them; Delete clears, typing replaces, copy is a table of them, pasted cells overwrite cells; native highlight hidden, cells tinted), `docx-view.ts` (FileView, toolbar, autosave).

## Rules

- Only `main.ts`, `*-view.ts` and `presentation/common/` import from `obsidian`. Other modules run under jsdom; they may use Obsidian's global DOM helpers `createEl`/`createDiv`/`createSpan` (shimmed in `tests/setup.ts`, which the directory scanner prefers over `document.createElement`) but nothing else Obsidian-specific. View tests (`tests/views.test.ts`) run the real views against `tests/obsidian-stub.ts`, aliased as `obsidian` in `vitest.config.mjs`; extend the stub only as far as a test needs.
- Writers must not touch what the user didn't change: unchanged runs/paragraphs/tables are cloned verbatim, edited ones only rewrite differing modeled props. Real-file tests assert byte-identical no-op writes for both formats.
- Manifest description must not contain "Obsidian". Avoid `!important`, `text-indent` and multi-column properties (`column-*`, `break-*: column`) in styles.css (directory CSS lint; `tests/columns.test.ts` checks the last); set those inline from code. View preferences go in `app.loadLocalStorage` / `saveLocalStorage`, never `window.localStorage`.
- Never dispatch transactions on load (image node views etc.) — opening a file must not save it.
- Keep OOXML child order valid (pptx: bullets before `tabLst`/`defRPr`; docx: `ORDER` table in docx-writer) — Office rejects misordered XML.
- Editor shortcuts that clash with app hotkeys (Ctrl+G...) go through the view's `Scope`, never a plain keydown listener.
- Autofit only runs after a text edit or an explicit resize/setting change; opening or clicking must not change the file.
- View type ids must be unique (`doc-works-*`); Office Suite already owns `docx-editor-view`.
- Spreadsheet writes go through `Sheet.setCell` / `setCached` (journaled, `touch`ed) or `Edits.structural` (whole parts); never edit sheet XML elsewhere or undo and dirty-only saving miss it.
- TDD: add a failing test (fixtures via `tests/fixtures/make_*_fixture.py`) before changing parser/writer behaviour.

## Known gaps (not in the README)

- Pivot table report filters (kept in the file, refreshed in Excel).
- GOOGLEFINANCE / IMPORTRANGE need the network; their saved results are shown.
- SmartArt items can't be added to cycle or hierarchy layouts.
- Complex floating objects don't match Office's layout exactly.

## Live testing in Obsidian

Vault: `~/notes`, plugin dir `~/notes/.obsidian/plugins/doc-works/`, scratch files in `~/notes/doc-works-test/`.

```bash
npm run build && cp main.js manifest.json styles.css ~/notes/.obsidian/plugins/doc-works/
obsidian plugin:reload id=doc-works && obsidian dev:errors
```

The CLI prints Electron GPU noise on stderr; add `2>/dev/null`. `obsidian dev:screenshot` output can lag a command behind; re-run it if the image looks stale. The user works in the same vault: open test files in a new tab and check `view.file.path` inside the same `obsidian eval` before any scripted edit.

## Generated files and releasing

- `tests/fixtures/sample.{pptx,docx}` come from `tests/fixtures/make_*_fixture.py` (python-pptx / python-docx). `src/presentation/pptx/font-metrics.ts` comes from `scripts/make_font_metrics.py` (fonttools), `src/domain/pptx/preset-shapes.ts` from `scripts/make_preset_shapes.py` (ECMA-376 presets), `src/domain/docx/line-heights.ts` (Word's single line height per font) from `scripts/make_line_heights.py`, `src/presentation/pptx/font-kerning.ts` from `scripts/make_font_kerning.py` (fonts: nixpkgs#carlito, nixpkgs#corefonts with NIXPKGS_ALLOW_UNFREE=1, Microsoft's Aptos zip).
- Release: bump `version` in `manifest.json`, `package.json` (+ both entries in `package-lock.json`) and `versions.json`, push a tag with exactly that version (no `v`). The workflow tests, builds and drafts a GitHub release; publish the draft so Obsidian sees it.
